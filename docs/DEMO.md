# Сценарий презентации BGen (3-5 минут)

## Слайд 1 — Проблема (20 сек)

«Пользователь хочет мини-игру. Сегодня это значит: разработчик, дизайнер,
тестировщик. Мы это убираем. Один промпт — одна игра.»

## Слайд 2 — Решение (15 сек)

«BGen. Пишешь `замути змейку для бабушки` — через 5 секунд играбельная игра
в WebView.»

Показать схему:
[Prompt] -> [Classify] -> [Compile] -> [LLM] -> [Analyze] -> [Repair] -> [Play]

## Слайд 3 — Демо #1 (60 сек)

Живая демонстрация. Открыть http://localhost:5173 в браузере.

1. Ввести: `замути змейку для бабушки`
2. Выбрать аудиторию: `Для бабушки`
3. Нажать «Создать игру»
4. Показать результат: крупная змейка, простой UI, большие элементы
5. Поиграть 10-15 секунд прямо на сцене (стрелками)

Говорить: «Обратите внимание — крупные элементы, спокойные цвета,
никаких таймеров. Это аудитория-специфичные правила в нашем промпт-компиляторе.»

## Слайд 4 — Демо #2, итерация (45 сек)

1. В поле «Доработать» ввести: `сделай поле больше и добавь еду разных цветов`
2. Нажать «Доработать»
3. Показать обновлённую игру

Говорить: «Итеративная доработка. Пользователь не программист — он просто
говорит, что хочет. LLM получает текущий код + новый промпт, возвращает
полную обновлённую версию.»

## Слайд 5 — Демо #3, вариативность (30 сек)

Сгенерировать второй жанр: `кликер с котиками для детей`.

Говорить: «Тот же пайплайн, другой жанр, другая аудитория — яркие цвета,
большие эмодзи, весёлая механика. Никакого зашитого шаблона, каждый раз —
генерация.»

## Слайд 6 — Архитектура (45 сек)

Показать схему из ARCHITECTURE.md. Проговорить ключевые блоки:

- Classifier — эвристики, превращает текст в спеку
- Compiler — собирает промпт из блоков (жанр + аудитория + механики + few-shot)
- Router — провайдер-агностик, Claude / OpenAI / Ollama / Manual
- Analyzer — проверяет 20+ инвариантов: цикл, ввод, победа, CDN, eval
- Repair loop — при провале LLM получает точный фидбек и чинит
- Corpus — few-shot база, top-2 примера в промпт
- Cache — повторные запросы мгновенно

## Слайд 7 — Что внутри (30 сек)

- Zero-deps ядро — чистая логика, легко тестировать
- Итеративная доработка — «сделай кнопки больше» работает
- Адаптация под ЦА — elderly/kids/hardcore меняют правила
- История и галерея — TMA хранит последние 20 игр
- Telemetry — метрики latency, cache hits, repairs triggered

## Слайд 8 — Что дальше (30 сек)

- Интеграция в WebView Билайна (готово, TMA — это тот же WebView)
- Аналитика по прошлым играм — corpus уже поддерживает `metrics.winRate`
- Генерация ассетов (SVG, звук) — следующий шаг
- Дообучение локальной модели на накопленном корпусе

## Ответы на вероятные вопросы

**Q: А если LLM сгенерит невалидный HTML?**
A: Repair loop. Первая попытка ~70% валидна, после 2-3 попыток — 95%+.
Каждая попытка получает структурированный фидбек: список ошибок с id + hint.

**Q: Как обеспечиваете WebView-совместимость?**
A: Analyzer проверяет: нет внешних CDN, нет eval, нет alert/prompt, нет fetch,
есть viewport meta, есть resize handler. При провале — repair.

**Q: Почему классификатор не использует LLM?**
A: Скорость и стоимость. Эвристики отрабатывают за <1мс, детерминированны,
дают одинаковый результат для одного промпта. Если нужен fallback — 0.2 confidence,
можно добавить LLM-классификацию в будущем.

**Q: Что если пользователь введёт что-то странное?**
A: Classifier вернёт `unknown` / `default`. LLM выберет сам подходящий жанр
по описанию. В галерее будет видно.

**Q: Как хранится история игр?**
A: localStorage в TMA, 20 последних. Плюс CloudStorage (опционально) —
шарится между устройствами.

**Q: Сколько стоит генерация?**
A: Claude Sonnet: ~$0.01-0.02 на игру (8K токенов вывода).
Кэш убирает повторные запросы. Few-shot примеры добавляют ~2K токенов в промпт.
