# Как работает промпт-компилятор BGen

## Идея

Промпт для LLM **не пишется одной строкой**. Он **компилируется** из блоков,
каждый из которых детерминирован и покрыт тестами.

UserInput ──▶ classify() ──▶ GameSpec
                                 │
                                 ▼
                    ┌────────────────────────┐
                    │  Compiler              │
                    │                        │
                    │  IDENTITY_BLOCK        │
                    │  HARD_RULES_BLOCK      │
                    │  genreRule(spec)       │
                    │  audienceRule(spec)    │
                    │  mechanicsBlock(spec)  │
                    │  examples (few-shot)   │
                    │  OUTPUT_FORMAT_BLOCK   │
                    │  QUALITY_REMINDER      │
                    └────────────────────────┘
                                 │
                                 ▼
                          CompiledPrompt
                        {system, user, spec}

## Классификатор

`classify(input)` работает на эвристиках:

- **Жанр** — по ключевым словам (`змейк` → snake, `кликер` → clicker, ...)
- **Аудитория** — `бабушк/дедушк` → elderly, `дет/ребён` → kids, `хардкор/про` → hardcore
- **Механики** — `растёт` → grow, `собира` → collect, `прыга` → jump, ...
- **Тема** — `космос`, `котики`, `дача`, ...
- **Ограничения** — для elderly автоматически: largeElements, highContrast, noTimer

Fallback-эвристики второго порядка:
- «карт» / «пазл» → puzzle
- «прыг» / «платф» → platformer

## Блоки системного промпта

### IDENTITY_BLOCK
Роль: «Ты — генератор self-contained HTML5-игр».

### HARD_RULES_BLOCK
11 жёстких правил: один файл, никаких CDN, никаких import/require,
обязательная структура start→gameplay→win/lose→restart, touch + keyboard + mouse,
viewport meta, resize, никаких плейсхолдеров, ≤60KB.

Это критично — без этих правил LLM тащит внешние скрипты, требует сервер,
делает не-играбельные огрызки.

### genreRule(spec)
Правила для конкретного жанра. Например, для snake:
- сетка 20x20
- движение с постоянным шагом
- управление стрелками + WASD + свайпами
- проигрыш при столкновении со стеной/хвостом
- счёт = длина змейки
- рестарт после проигрыша

### audienceRule(spec)
Правила для аудитории. Самая важная — для elderly:
- все кликабельные элементы ≥ 60x60
- шрифт ≥ 20px
- максимальный контраст
- никаких таймеров на реакцию
- максимум 2 действия одновременно
- спокойные цвета

Для kids: яркие цвета, эмодзи, мгновенный фидбек, никаких проигрышей в первые 10 сек.

### mechanicsBlock(spec)
Микро-правила по механикам, вставляются только если найдены:
- `grow` — «объект растёт при выполнении условия»
- `collect` — «сбор предметов = +счёт»
- ...

### Few-shot examples
Из корпуса достаются 2 игры с наиболее близкой спекой.
Вставляются в системный промпт как примеры HTML.

Дают LLM якорь структуры и стиля.

### OUTPUT_FORMAT_BLOCK
Формат ответа: только `<html>...</html>`, ничего до и после,
рекомендуемая структура кода (шаги 1-7).

## Пользовательский промпт

Простой запрос:

Сгенерируй игру по запросу пользователя.

ЗАПРОС ПОЛЬЗОВАТЕЛЯ:
"замути змейку для бабушки"

РАЗОБРАННАЯ СПЕЦИФИКАЦИЯ:
ЖАНР: snake
АУДИТОРИЯ: elderly
ОБЯЗАТЕЛЬНЫЕ МЕХАНИКИ: grow, collect, score
ОГРАНИЧЕНИЯ: touch-управление обязательно; без таймеров; крупные элементы (60px+)

Верни готовый HTML-файл. Только код.

Итерация (доработка):

Пользователь уже получил игру и хочет доработать её.

ИСХОДНЫЙ ЗАПРОС: "замути змейку"

ТЕКУЩИЙ КОД ИГРЫ:
[полный HTML предыдущей игры]

НОВЫЙ ЗАПРОС НА ДОРАБОТКУ: "сделай кнопки больше"

ПРАВИЛА ДОРАБОТКИ:
- Сохрани всё, что не противоречит новому запросу.
- Верни ПОЛНЫЙ обновлённый HTML-файл, а не diff и не фрагмент.
- Не ломай существующие механики.
- Только код.

## Repair loop

Если анализ провален, LLM получает:

ПРЕДЫДУЩАЯ ГЕНЕРАЦИЯ НЕ ПРОШЛА ПРОВЕРКУ.

КРИТИЧНЫЕ ОШИБКИ (обязательно исправить):
- [no-game-loop] Нет игрового цикла
  -> Добавь requestAnimationFrame(loop).
- [no-input] Нет ни одного обработчика ввода
  -> Добавь keydown, touchstart, pointerdown.

ПРЕДУПРЕЖДЕНИЯ (желательно исправить):
- [no-score] Нет счёта в UI
  -> Отобрази счёт крупным шрифтом.

ВОТ ТЕКУЩИЙ КОД:
[текущий HTML]

ИСПРАВЬ УКАЗАННЫЕ ПРОБЛЕМЫ.
Требования:
- Верни ПОЛНЫЙ HTML-файл (не diff).
- Сохрани всё, что работает.
- Только код.

## Как докручивать промпты

1. Прогнать `bun tools/src/test-prompts.ts` — проверить classifier
2. Сгенерировать 5-10 игр через реальную LLM
3. Записать проблемные случаи (какие warnings чаще всего)
4. Добавить правило в `blocks.ts` / `genres.ts` / `audiences.ts`
5. Повторить

## Антипаттерны

НЕЛЬЗЯ:
- «Сделай игру на любую тему» — слишком расплывчато
- «Пусть будет красиво» — LLM не понимает субъективных пожеланий
- Промпты длиннее 500 символов — дорого и часто сбивает LLM

ПРАВИЛЬНО:
- «замути змейку для бабушки» — коротко, есть жанр + аудитория
- «кликер с котиками для детей» — есть тема
- «сложный раннер для про» — есть аудитория (хардкор)
